# Reliability review and offline validation, 2026-10-15

This folder remains a standalone legacy bot, not a DesktopStub provider or a
shared native application overlay. Its existing user configuration and runtime
data have been preserved. No staging, commit, publication or deployment was
performed during this review.

## Fixed in source

- Watchdog restart timers remain referenced after a crash. Spawn errors and exit
  events cannot schedule duplicate restarts; signal-delivery errors on a live
  child are not mistaken for its exit. Backoff and the ten-restart bound remain.
- Shutdown tracks the actual child exit rather than `ChildProcess.killed`.
  Supervised children receive an IPC shutdown request, allowing normal cleanup
  on Windows, followed by SIGKILL if the child still has not exited after ten
  seconds. Intentional exit and self-update code 75 do not restart the child.
- `run-bot.cmd`, `npm start` and the existing Startup launcher all select the
  watchdog. The explicit `start:direct` debug route remains available.
- Gateway leadership has an independent monotonic deadline during login and
  renewal. It aborts in-flight login and disconnects the published/in-progress
  client when ownership expires. Late acquire/renew results cannot restore an
  expired generation. Delayed acquires release only their own lease epoch.
- Gateway lease traffic uses a dedicated bounded PostgreSQL pool; renewals do
  not queue behind history/cache queries and cannot revive an expired row.
  The general pool also has bounded client/server query durations.
- Independent voice HA now uses the same lease core, including bounded,
  cancellable warm-standby preparation and independently fenced target refresh.
  Its in-progress login is published before awaiting login so cancellation can
  destroy it. Every awaited join step checks the current ownership signal;
  stale continuations cannot join or destroy a replacement owner's connection.
  Optional lifecycle logging no longer postpones the next lease renewal.
- Startup names include a stable project/node hash, preserving distinct IDs
  that share a sanitized prefix or differ only after the old truncation limit.
  Managed markers prevent overwriting/removing unrelated entries. Exact known
  legacy launchers are removed only after successful new publication. Batch
  paths preserve percent, exclamation, metacharacters and Unicode without
  interpolating the node ID as executable batch text.
- Monthly archives use a repeatable-read, read-only transaction with two SQL
  cursors fetched in batches of 128 rows. JSONL passes through backpressured
  compression/output streams. Successful snapshot completion precedes atomic
  publication; failures remove only the temporary file and preserve an older
  archive. An uncertain rollback discards the database connection.
- Direct and Startup launches resolve the installed Windows npm CLI without
  requiring npm's inherited environment. Explicit `NIFIBOT_NPM_CLI`, inherited
  `npm_execpath`, normal Node/npm and roaming/PATH installations are supported.
  The CLI runs through the current Node executable without a `.cmd` shell.
- Unix socket recovery is serialized and requires connection refusal plus a
  stable socket device/inode. Active, uncertain, replaced and ordinary-file
  paths are not removed. Normal close relies on Node's own unlink; a second
  unlink could otherwise remove another process's replacement socket.
- `history-staging/`, `archives/` and `.offline-tests/` are now ignored alongside
  the existing secrets/logs/build/dependency/update exclusions. Existing guild
  history data was not read or deleted.

## Validation actually performed

Installed runtime: Node v26.11.1, using the already installed TypeScript compiler.
No dependency installation was needed.

Full source compilation succeeded with:

```text
node node_modules/typescript/bin/tsc --project tsconfig.json --outDir .offline-tests --sourceMap false --pretty false
```

The final bounded offline runner succeeded with all 27 tests passing, zero
failures, and about 0.18 seconds reported duration:

```text
node --test --test-timeout=10000 tests/offline.test.mjs
```

The tests import only the dependency-injected runtime modules. Fake children,
timers, monotonic time, stores, filesystem predicates and socket probes cover
crash restart, spawn/exit duplication, clean/self-update exits, shutdown escalation,
IPC cleanup, restart limits, hung login/renew/acquire, late results, delayed timer
dispatch, normal renewal, shutdown cancellation, npm discovery, conservative
socket-recovery decisions, hung voice preparation/refresh, no-target standby,
Startup collision/quoting/ownership/failure preservation, archive paging,
successful JSONL compression and failed-write/commit publication preservation.

No production configuration module or `.env` was loaded by these fixtures.
No supervised application child, bot, gateway, database, player, socket listener, Startup entry, package
installation, migration, command deployment or update was started. Compilation
emitted only to ignored `.offline-tests/`; the user's normal `dist/` and any
running instance were left untouched. Local ignore checks confirmed the new
history/archive/test-output exclusions.

Real multi-node failover, a real stalled PostgreSQL connection, Windows IPC
shutdown, Unix socket recovery and installed npm layouts outside the fake cases
still need deliberate integration acceptance. Generated Startup batch execution
on the supported Windows versions and actual PostgreSQL cursor/snapshot behavior
also remain integration checks; offline tests never run these operations.
Timers cannot execute while the
JavaScript event loop or machine is suspended; monotonic continuation checks
prevent accepting a result after the local deadline once execution resumes.

## Limits and remaining decisions

- Archive memory is bounded by a fetched batch, stream buffers and individual
  record serialization rather than the full month. An exceptionally large
  individual database JSON row still requires memory for that row. Database
  sort/work memory is managed by PostgreSQL rather than this application.
- A very large archive holds a read snapshot/connection until completion;
  concurrent ingestion, retention and pooling behavior should be verified
  against the actual deployment. Existing fifteen-second per-query bounds
  apply to counts/declarations/fetches; the archive is not preloaded on Node.
- Voice join/synchronization timing still needs acceptance with the deployment's
  actual target count and network latency. Work that exceeds the configured
  ownership deadline yields rather than continuing under an expired lease.
- Unknown/colliding older Startup launchers are intentionally preserved. An
  older launcher from a changed Node location may require an owner review
  because it no longer exactly matches the known legacy template.
- The existing broad remote computer/update capability, database TLS policy and
  credential storage have not been redesigned. The README now explains the
  danger and existing optional user restriction. Extra protection remains a
  separate opt-in/user-setup decision, not a new mandatory migration condition.
