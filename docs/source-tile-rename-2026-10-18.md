# Explicit source tile renaming

Explicit-name propagation is installed with the first October 18 CPU repair. The implementing agent used source review; the parent performed the coordinated build, scan and bounded validation below. Actual interactive Start rename acceptance remains separate.

Explicit `Tile.<source>.Name` edits now have a separate name-only path for the six fixed source tiles. The tray save, normal CLI transaction, and configure-only transaction stage a durable intent in the same atomic INI candidate as the Name edit. `[State.SourceTileNames]` holds at most six pending names plus a monotonic Sequence. Each entry encodes its revision and desired name. A later registered launch can honor that explicit record even if the edit was made while the app was closed. A normal launch with no explicit record only seeds the observed configuration baseline, preserving an existing native user rename.

Raw INI Name changes while the resident is running are observed using the existing copied configuration document. Polling posts a coalesced UI notice; it never calls native tile mutation. The UI persists that change before attempting native work. Feed URL changes, other source data, appearance migration and ordinary startup/reload do not schedule renames. Manual raw Name edits while the app is closed have no explicit durable marker and therefore seed the next baseline; use tray Rename or `--configure-only --set Tile.rss.Name="My feed"` for an offline edit that must update the native name on the next launch.

Native work finds the already-pinned object with `FindAllAsync`, writes only `SecondaryTile.DisplayName`, and calls its `UpdateAsync`. It never creates or deletes a tile, replaces its ID, changes activation arguments/logos, clears notifications, or selects a Start position. Work is serialized with pin and appearance operations so queued stale tile objects cannot undo a later appearance update. Latest names coalesce; stale queued revisions are fenced before mutation. Success clears only the matching revision and value. A missing pin also clears that intent because a later explicit pin already uses the saved Name. Enumeration/update failures and unavailable package identity preserve the intent for a later explicit retry or restart; unchanged polls do not issue repeated native attempts.

`dependencies/secondary_tile_rename.h` contains the pure observer, bounded revision reader and property-selection helper. `DesktopStub/tools/SourceTileRenameHostTests.inc` exports `TestSourceTileRenameHost()`. Its fake tile verifies unchanged ID, arguments, logos and position; injected notices cover startup/feed/appearance exclusions, raw/tray Name changes, coalescing, post failure, atomic rejection, durable configure-only intent, restart consumption and stale completion fencing. The only file writes in those fixtures target the existing private host-test profile. Root owns registration, fresh compilation, scanning and inert runs; this agent performed source/whitespace review only.

Idle polling now reuses an immutable fingerprint/name/intent view keyed by absolute profile and `g_iniCacheRevision`. Every lookup first takes the existing named profile lock, refreshes the normal INI cache at its unchanged configured interval, and checks profile binding. It copies/parses the full document only after a revision or profile change; unchanged invalid configurations reuse their refusal. Live pin selection is separate from this view. The normal INI cache records its absolute profile even when new bytes equal the previous profile. Its revision advances on initial/reloaded publication, changed bytes, or changed profile. `ReadIniSectionCached` has an optional `cacheReady` result: successful refresh of a sparse file sets it true even if the requested section is absent; I/O or profile failure leaves it false. Failed refreshes cannot acquire a new fresh interval from stale bytes. Added source fixtures count derived parses and cover unchanged polls, Name/appearance/intent revisions, cached invalidity, named-lock refusal, same-profile refresh failure and missing-profile refusal. The parent validated and installed these changes with the second CPU repair: all 174 extended host and 14,427 core host checks, exact rendering and copied-binary offline smoke passed. See the coordinated CPU record for hashes and startup health. Interactive native name/placement acceptance remains a normal-use check.
