# Photo gallery setup and Windows tile integration

The original gallery build and its validation are recorded in the
[validation record](gallery-validation-2026-10-15.md). The later scale, folders,
pin batching and UI changes are tracked in the
[follow-up record](tile-feedback-followup-2026-10-15.md); use that record for the
current build's validation and installation state.

The gallery shares DesktopStub's process, INI, providers and Windows notification transport. It adds no resident executable or DLL. Its menu is **Tiles > Photo galleries**. Choose **Set up gallery...**, select a filesystem folder, and choose 1–1,024 tiles. Setups above eight tiles use numbered names, which can be renamed afterward. Setup queues the Windows pin confirmations one at a time. **Pin all gallery tiles...** repeats that queue for configured tiles; Windows still owns each confirmation and the timing of queued images.

Each gallery's **Number of tiles...** changes its size. Expanding an already populated gallery offers explicit redistribution: old photo queues must be cleared successfully before a new ownership epoch is saved. Native tile IDs, names and Start positions are retained. **Add another gallery folder...** creates a separately named group with its own folder and count. Subfolders are included within the documented traversal bounds; directory reparse points are skipped.

Setup needs the registered packaged launch so Windows can enumerate this app's actual secondary tiles. A successful enumeration checks **all** `AipGallery_` IDs, including unknown historical groups. An empty cached menu, failed query or query still in progress cannot authorize new ownership history. The query times out after 15 seconds without creating history. Existing gallery pins, an established configuration with a missing ledger, or a corrupt/populated ledger cause refusal instead of silently assigning old photos to new tiles.

The selected profile and its `<profile>.gallery-ledger` belong together. Setup creates that ledger without replacement before publishing the INI. If the INI commit fails, the unused ledger remains and setup can reuse its original group/epoch on retry. It never deletes history to recover. Ordinary folder, order, fit, queue-length and refresh changes use the existing ledger. Unpinning or removing a photograph does not transfer its reservation to another tile. Only the separately confirmed redistribution workflow may start a new ownership epoch.

First setup also stages a valid shared tile baseline: absent source-tile Enabled flags become disabled, existing explicit flags/mappings remain, and Content.Count grows only when an explicitly enabled source mapping requires it. Existing numbered content and accounts are preserved. Active legacy TileText values or a legacy RSS primary source migrate only into absent primary content fields; disabled legacy custom text stays inactive. Gallery saves validate the complete candidate profile, so enabling gallery mode cannot publish out-of-range source mappings that stop both gallery and primary delivery.

All ordinary controls have typed INI/`--set` counterparts: `[Gallery]` has `GroupId`, `Folder`, `TileCount`, `QueueSize`, `RefreshSeconds`, `Order`, `Fit`, and `Seed`; `[Gallery.Tile.N]` has `Id`, `Name`, `Folder`, `GalleryName`, `Background`, `BackgroundColor`, and `Branding`. Old `Enabled` fields remain readable for compatibility; pinned destinations determine updates. Identity fields are generated by setup and should be kept with their ledger. Shared full-profile and locked candidate validation reject invalid ranges, duplicate tile identities, multiline values and invalid appearance choices. An inaccessible folder can remain configured while offline; clicking **Open photo folder** reports its unavailability.

Gallery tiles default to transparent artwork with the tile name and no corner branding logo. Per-tile appearance uses the same choices as the six source tiles. Existing known pins receive appearance updates in place through the established main-thread migration. CLI/reload/external INI appearance changes enter its coalesced fingerprint; names, photo folders, account fields and queue cadence do not cause native enumeration. The fallback uses the native Segoe Photo glyph `E91B`, with the repository's vector photo icon when the installed fonts lack it. Artwork never takes an unreserved photograph as a static logo.

Each native ID is generated as `AipGallery_<group>.<tile>` and matched against configured complete IDs. Components can contain underscores; the native API never guesses their boundary. Static pin and notification activation carry the selected `--ini` profile and `--open-folder` directory. Windows `/tileid` metadata can resolve the current folder from that profile, including after a configured folder change. Unknown historical IDs produce an explanation without launching a new resident. Relative directories are resolved beside the selected INI. Only an existing directory reaches the shell-open boundary; no command shell is used. The utility returns before INI creation, provider startup, package registration or Startup integration.

`DesktopStub/tools/GallerySetupHostTests.inc` covers inert typed/candidate/full-profile validation, historical-pin refusal, retained-empty-ledger recovery policy, full-ID matching, metadata fingerprints, folder activation and menu structure. `GalleryUiFlowHostTests.inc` exercises private configuration/ledger expansion with an injected queue-clearing boundary. `GalleryPinBatchHostTests.inc` covers serial pin queue and pin inventory logic. Native folder-chooser, pin-confirmation and Start-animation acceptance remains a local Windows check.
