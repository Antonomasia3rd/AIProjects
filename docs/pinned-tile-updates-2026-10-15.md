# Pinned tiles and sequential confirmations

Source tiles now use Start pin membership to decide which mapped providers and frames are needed. A pinned source keeps updating despite the older saved Content/Tiles/Tile.Enabled flags; the source-specific “Update this tile” and “Update source tiles from this app” checkboxes are retired. Turn Live Tile display off on Start to pause what Windows shows, or unpin a tile to remove its source demand. Original primary content fields and saved preferences remain in the INI; membership selection is in memory.

The pin inventory comes from a successful asynchronous enumeration of all secondary IDs, including historical galleries not found in the current INI. The UI owns enumeration/results. Polling posts a coalesced request at most every 30 seconds, and acknowledged application pin/unpin operations amend the cache immediately. Failed enumeration preserves the last successful snapshot and waits before retrying. Frame/menu membership checks use a mutex-protected set lookup without synchronous WinRT Exists calls or copying the entire inventory for each tile. Default inert validation does not enumerate real tiles.

Pin all for Gallery or Quick Actions uses one shared queue. Only one Windows confirmation is active; No, cancel, terminal error or a preparation failure finishes that item and advances to the next. Duplicate pending IDs are coalesced. Shutdown empties the queue and cancels pending operations. There is no custom visible DesktopStub owner window. Native requests initialize against the existing main HWND and use the cursor selection rectangle to anchor the Windows confirmation, through [SecondaryTile.RequestCreateForSelectionAsync](https://learn.microsoft.com/en-us/uwp/api/windows.ui.startscreen.secondarytile.requestcreateforselectionasync).

The API exposes `ClearGalleryQueuesForRebalance` only for an explicit confirmed redistribution workflow after gallery delivery is paused and generation drained. It checks actual pinned state, clears those historical gallery notification queues, and preserves pin IDs/names/Start placement. Every requested clear must finish before ownership is reset. It is unavailable in default inert validation.

New/changeable tray labels read the existing Strings section: `SourceTilesSetup`, `SourceTilesSetupPrompt`, `PinTile`, and `QuickActionsPinAll`. Status content uses the separate cached size-aware formatter. Existing pin/appearance/account settings remain configurable.

`tools/SecondaryTileTests.cpp` adds portable fake batch, inventory cadence/failure, immediate acknowledgement and pinned-selection coverage. `DesktopStub/tools/GalleryPinBatchHostTests.inc` adds inert host configuration/menu tests and verifies the default boundaries cannot pin or clear actual Windows queues. Parent compilation, scans and bounded checks passed; see the [final validation](tile-feedback-followup-2026-10-15.md). Actual native batch confirmation acceptance remains a local Windows check.
