# Notes rows and prepared tile status

Source checkpoint: original game icons now accompany each Notes resource/activity row on the left in adaptive XML and bitmap fallback. Each row carries an opaque `Text.iconTopic`, selected from its game, resource state, and detail kind. Delivery and generated-image keys include that topic. The original 23 ICO resources, generated exact-byte header, MIT license, and provenance are preserved in `dependencies/third_party/RealTimeNotesAssets`. They were extracted from repository history `89d26e5^`, never downloaded and never read from account data. Star Rail Reserve reuses that game's stamina icon because the donor has no separate Reserve asset.

The supported Windows ICO decoder reads compiled, bounded bytes (at most 64 KiB and 128×128 pixels). Native notifications use immutable versioned PNG assets produced from those bytes. Bitmap fallback decodes the same originals; unavailable original artwork uses the resource glyph or full-width text without an empty icon column. There is no Windows 11 glyph preference for game artwork.

`ga_tile_status.inc` exports `BuildTileStatusText(const std::vector<aip::content::Snapshot>&)`. It reads prepared snapshots and configurable strings. It does not fetch sources, query native pins, read images, or infer Windows' visible queue entry. RSS and Notes status uses the actual structured headlines/rows, with the renderer's three-row Medium/Wide and five-row Large caps. Different size variants are labeled separately. Scalar/media fields retain actual current playback metadata. Tile blocks have a blank line between them. Gallery blocks list cached slot/tag/thumbnail names and explicitly describe a prepared queue; they do not expose full cache paths or claim which image is visible.

New `[Strings]` keys are `TileStatusPrimary`, `TileStatusMediumWide`, `TileStatusLarge`, `TileStatusNoSnapshot`, `TileStatusTextHidden`, `TileStatusImage`, `TileStatusQueue`, and `TileStatusSlot`. Notes row labels use `NotesResin`, `NotesPower`, `NotesCharge`, `NotesFull`, `NotesFullIn`, `NotesDetailUnavailable`, `NotesDetailUnsupported`, `NotesUnavailable`, `NotesExpeditionsReady`, plus `NotesDetail` followed by the existing detail value (for example, `NotesDetailWeeklyBosses`). Labels are captured with prepared rows; custom wording preserves source counts and icon identity. These keys use the existing Strings editing/CLI route.

Added source fixtures cover game-specific original icon selection, every supported detail's embedded icon, original full/error states, configurable labels, per-row escaped native XML, bounded disjoint bitmap row geometry, missing-artwork fallback, status field/size parity, media state, queue disclosure, and decoding/rendering the embedded originals offscreen. `DesktopStub/tools/TileStatusHostTests.inc` exports `TestTileStatusHost()` for the host fixture. Parent build, scans and inert validation passed. A real-startup graphics lifetime defect was also diagnosed and fixed, with a fresh-icon regression that begins with GDI+ unloaded; see the [final validation](tile-feedback-followup-2026-10-15.md). Native Start layout acceptance still depends on Windows' notification rendering and tile size, which the status dialog cannot query from a prepared snapshot.
