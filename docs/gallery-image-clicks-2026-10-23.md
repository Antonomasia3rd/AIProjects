# Gallery clicks identify the Windows notification

`Gallery.Tile.N.ClickAction=Image` is the default. A Live Tile notification now carries an opaque token identifying its gallery, tile, ownership epoch, and content hash. The token contains no original photo path. On a click, DesktopStub reads the first `RecentlyShownNotifications` item reported by Windows and resolves that exact notification through its owned image record. It does not infer the visible image from the most recently submitted frame or the queue cursor.

Microsoft documents this as [chaseable tile notifications](https://learn.microsoft.com/en-us/windows/uwp/launch-resume/chaseable-tile-notifications). Visual arguments arrive through `LaunchActivatedEventArgs.TileActivatedInfo`; they do not replace ordinary application launch arguments. Desktop applications can retrieve activation data with `AppInstance.GetActivatedEventArgs` on supported systems. This implementation uses an uncached activation factory and balanced apartment initialization. Real activation metadata availability for DesktopStub's full-trust launch path still requires native acceptance testing.

Before publishing, DesktopStub saves an original-file record under `<INI>.gallery-clicks`. Records are scoped to the Windows user and INI profile. Opening requires a matching configured tile, current ledger ownership and epoch, supported local image extension, unchanged file identity/size/write time, and a final canonical path inside the configured gallery root. The default image association opens the photo. There is no general file-execution command: `--gallery-image` accepts an opaque ownership token, not a file path.

When Windows supplies no exact metadata, a record is unavailable, or the original file changed or moved, DesktopStub opens the gallery folder and offers an informational notification. Registration images have no chaseable notification metadata, so they use this fallback too. DesktopStub never substitutes a guessed or last-submitted image. `ClickAction=Setup` instead opens the selected tile's settings, through the resident where available.

The same activation reader now lets a configured RSS source tile consume its notification's validated source URL. Tile identity and INI profile must match before that URL is accepted.

Validation uses synthetic activation metadata and an injected photo viewer. It never invokes Windows activation metadata APIs, opens actual photos, changes packages, or pins a tile. The portable fixture covers opaque payloads, ownership, parsing limits, and extension/path rejection; the combined host fixture covers actual XML, command-line parsing, early activation dispatch, original-path resolution and safe metadata absence. Include `.gallery-clicks` with configuration/ledger backups when resetting or moving a profile.
