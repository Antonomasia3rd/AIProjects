# Interrupted gallery changes and stale dialogs

Gallery redistribution now has a recovery record beside the selected profile, named `<profile>.gallery-transaction`. It contains canonical gallery settings for the old/new endpoints, the old ownership ledger, and the requested new epoch. It does not copy the complete INI, account fields, tokens, or credentials. The record can contain image identities from the ledger and should be kept with the private profile/ledger until recovery finishes. Both runtime extensions are ignored by Git.

Redistribution holds the generation boundary, suspends gallery publication, and compares the dialog's original gallery configuration with the freshly locked INI before clearing anything. It validates the complete candidate and matching ledger group, writes the recovery record without replacing an existing record, clears historical queues, resets the ledger using its expected bytes, and atomically publishes the INI. Removing the recovery record is the last step. A pending record fences configuration capture and frame validation so the unused reset ledger cannot allocate new owners before recovery.

If final INI publication fails, recovery restores the exact old ledger only when the INI is still the old gallery configuration and the ledger exactly equals this transaction's unused reset. This preserves every historical owner, ordinal, epoch, cursor and pending window. Queues can then refill from that ownership. A failure restoring ownership or removing the record leaves publication paused and retains recovery data for retry.

Startup attempts recovery before gallery providers or the initial composed frame. The menu also exposes **Recover interrupted change...** when a record is present. Recovery never rewrites the INI, so unrelated/account changes stay intact. It cancels a record whose files are still at the old endpoint, finishes cleanup for the committed new endpoint, or restores the old ledger after an interrupted reset. If old/new gallery settings are identical, an already-reset ledger is the intended explicit redistribution endpoint. Unexpected gallery or ledger edits cause refusal with the record preserved; recovery does not guess a replacement history. Keep the record and restore the matching profile/ledger before retrying.

Add-folder, resize, folder-selection, rename, appearance, cadence and seed dialogs carry their original profile/gallery context through saving. A changed gallery or selected profile causes refusal instead of overwriting newer settings. Unrelated INI edits are accepted and preserved. The existing first-setup comparison and create-only empty-ledger retry remain in place.

The existing `GalleryUiFlowHostTests.inc` now includes private-file and injected-boundary cases for final INI failure, interruptions after journal/reset/INI publication, failed restore followed by retry, ambiguous external edits, unchanged-configuration redistribution, stale add/resize/folder/profile contexts, and preservation of unrelated account edits. Codec cases reject malformed lengths and trailing bytes.
