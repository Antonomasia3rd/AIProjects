# ASUS blink/status native engine

Scope: port the active behavior of `dependencies/asusblink/asusblink_app.cs` into a native reusable engine for DesktopStub. Keep the standalone C# program until functional parity is demonstrated. Validation must never open ATKACPI, send firmware requests, change LEDs/backlight/microphone/audio, or sample real hardware.

## Active behavior inventory from code

- Two output devices are actually used: mic-mute indicator LED (`SetMicLed`) and keyboard brightness/state (`SetKeyboardState`). The app does not change the microphone's audio mute setting.
- Mic states are integers 0–1; keyboard states are 0–255. Each event has a state sequence, wrapping interval sequence and duration. `off` disables an event; `once` runs one cycle; duration 0 runs indefinitely; positive duration counts active, unpaused time.
- Base mic and keyboard events coexist with numbered events. Events for the same device run serially in ascending numeric priority. An indefinitely running earlier event prevents later events from running.
- Numbered HDD events map disk activity levels 0–4 to keyboard states, clamping to the last available state. Boundaries are 0, 100 KiB/s, 1 MiB/s and 10 MiB/s. A one-shot HDD event samples once; repeating HDD events use their first interval, defaulting to 500 ms.
- Zero-interval, infinite ordinary events hold and reapply one state every 200 ms. Finite zero-interval events use a 200 ms step. One-cycle zero-interval events advance immediately.
- Pause/resume and cancellation stop progress cooperatively. Applying a state retries up to ErrorRetry (0–100) with 500 ms between attempts. ErrorAction supports continue/log, pause, exit and crash in the standalone process. Embedded equivalents must affect only the engine, never crash or terminate DesktopStub.
- Active ACPI protocol: device `\\.\ATKACPI`, IOCTL `0x0022240C`, method DEVS `0x53564544`, arguments device ID and state, 16-byte response with at least four bytes and result 1 required. DeviceGet and fan/GPU/performance constants exist but are not used by the application's active blink loop and are outside this port.
- Legacy host behavior (INI migration, tray, logging, Startup, CLI and process controls) stays in shared DesktopStub host code and is not duplicated inside the engine.

## Proposed API/files

Namespace `aip::asus`: platform-neutral `Configuration`, `Event`, `PatternEngine` and snapshot/state selection under `dependencies/asusblink/pattern.h`; a separately compiled Windows ACPI backend under `dependencies/asusblink/native_backend.*`; an owned cancellable service and a tile-text adapter under the same dependencies/content_sources layout. Hardware actions default disabled and are a separate explicit option from enabling a preview/status source. Pure pattern stepping accepts timestamps and supplied HDD samples for deterministic tests. The backend is injected, so tests use fake outputs and never construct the native backend.

Concrete files now exist: `pattern.h` contains configuration, event/time parsing, a legacy Settings-map adapter, and deterministic per-device pattern stepping; `service.h`/`service.cpp` own cancellable lifecycle and backend injection; `protocol.h` constructs only the active DEVS request; `native_backend.cpp` implements lazy ATKACPI writes and separately gated read-only PDH disk sampling; `content_sources/asus.h` maps snapshots to tile text.

API: `aip::asus::Service::Start/Reload(Options,error)`, `Pause(bool)`, `Stop(timeoutMs)->bool`, and `Read()->Snapshot`. Options separately default `hardwareEnabled=false` and `readDiskActivity=false`. Merely constructing the service or enabling preview never constructs its backend. Native backend construction itself does no I/O; ATKACPI opens only inside an explicitly enabled `Apply`. Snapshot separates requested pattern states from successfully applied states, and reports preview/control, pause, completion, error and source-fault status. `ErrorAction=exit/crash` stops/faults only this engine; no host process termination is implemented.

Public `ParseConfiguration(map<wstring,wstring>, Configuration&, error)` now accepts the active legacy `[Settings]` schema (base and numbered mic/keyboard/HDD events, timing units, retry/error actions). It is transactional, checks aliases/bounds, and recognizes host-only tray/Startup/log preferences without applying them. `ParseEvent` supports direct inline host controls.

`tools/AsusEngineTests.cpp` covers protocol bytes, parser failures, priorities, state/interval wrapping, active-time pause/resume, once/timed/infinite semantics, zero-interval holds, HDD thresholds/final samples, 100,000 randomized scheduler steps and fake-backend service preview/control/cancellation/fault behavior. `tools/TestAsusEngine.cmd` compiles the native backend only, then links the fixture executable with `AIP_ASUS_NO_NATIVE_BACKEND`; a test cannot open the real driver even if an injection regression occurs.

The first native compile/fixture batch **passed: 287,637 checks and 100,000 randomized steps** (`build/asus-engine-tests.log`). Native backend, portable service and fixture tests compiled under MSVC `/W4 /WX` without warnings. The fixture binary excludes the native backend. No driver, LED, microphone or disk-counter access was exercised.

CMake and Windows CI now include the fixture suite; CI compiles the native backend without executing it. DesktopStub declares a narrowly routed native ASUS engine dependency; legacy C# implementation changes remain asusblink-owned. Project-map validation passed for 14 projects, and workflow consumer selection passed for 14 projects plus All. The shared `hardware` namespace introduced by the parallel caps indicator work is recognized by the map validator.

Clang also passed the fixture suite. A follow-up compatibility check removed an invented total-event cap: the C# parser explicitly accepts event IDs spelled with one to three digits, including distinct leading-zero names. The native parser keeps that exact ID grammar and does not add a separate event-count restriction. The final Clang fixture run includes this case: **287,638 checks, 100,000 randomized steps passed** (`build/asus-portable-tests.log`). The earlier native MSVC `/W4 /WX` pass had 287,637 checks before that extra regression case was added. Root owns DesktopStub catalog, configuration and menu integration.

Host contract: link `dependencies/asusblink/service.cpp` and `native_backend.cpp` as separate translation units, adding `pdh.lib` on Windows. Start with `Options.hardwareEnabled=false` and `readDiskActivity=false`; supply parsed Configuration. `Read()` returns requested pattern states, separately recorded applied states, active event names, completion, pause, error and fault status. No initial LED state is inferred, and stopping does not invent a restoration write. As in the C# implementation, the final successfully requested hardware state can remain after stopping.

Parity/verification limits: the active DEVS packet and pattern timing rules are ported and fixture-tested. Actual ATKACPI driver support for overlapped requests and physical indicator behavior remain unverified. The service reports a pending Stop timeout if a driver does not acknowledge cancellation; worker-owned request buffers remain alive instead of being freed under kernel I/O. The module must remain loaded during pending cleanup. Native execution serializes a tick's mic/keyboard requests; error/retry ordering between devices can differ from the legacy pair of worker tasks. Standalone C# is retained until those hardware/host behavior checks can be completed by the user in an appropriate environment.

The Discord CI selector follow-up is complete: filename-boundary matching fixed a false `service.cpp` match in `SecureDesktopLauncherService.cpp`, and the workflow selector passed for all 14 projects plus All.
