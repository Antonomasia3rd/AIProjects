# App launcher tiles

Create **Tiles > Add tile > App launcher**, then open its Source settings. Choose a program/document with the file picker or enter a full path, a program name ending in `.exe`/`.com`, or a URL. The tile opens that configured target when clicked. **Click action > Open this tile's settings** remains available. Creating or configuring the tile does not start its target or pin anything automatically.

Program arguments and the optional working directory are separate settings. DesktopStub passes them separately to Windows [ShellExecuteEx](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw); it does not construct a command-interpreter or script-wrapper command. Registered document/URL associations still determine what Windows opens. URL targets cannot have separate program arguments. Activation arguments contain the existing profile and tile ID, while the current validated tile configuration supplies the target. Environment variables are expanded for filesystem paths, not for URLs or program arguments.

`Launcher.Target`, `Arguments`, `WorkingDirectory`, `IconMode`, `IconPath`, `IconIndex` and `IconSizePercent` belong to each `Tile.<id>` section. They are available through the same INI, generic `--set`, tray and Properties command surfaces. `ClickAction=launch` is the App launcher default and is rejected for other tile types. An empty target is a valid configuration awaiting setup; clicking it cannot launch a default program by accident.

The native static artwork supplies Small, Medium, Wide and Large canvases plus the small branding logos. Auto selects a fully local program icon or the Windows file-association icon; an unavailable icon uses DesktopStub's own application symbol. Custom supports local PNG/JPEG/BMP/GIF images and ICO/EXE/DLL icon resources. The index can select a resource; negative values identify an icon resource ID. Icon size is 10–100% of the shorter tile side, preserving image proportions. None hides the icon, and the existing tile background/name controls remain applicable. An icon picker saves the chosen file, Custom mode and index zero together.

Background artwork does not probe a remote target, download a URL icon, resolve a cloud placeholder or follow a linked icon path. A UNC target can still be explicitly opened by clicking its tile; it uses fallback/custom local artwork. Bare executable names are left for Windows activation to resolve and use fallback artwork unless a custom local icon is selected. Cached artwork paths contain only hashed ownership/configuration information. The existing pin/update machinery applies these assets; no extra resident or polling timer is introduced by the launcher module.

Validation: the focused fixture passed **73 checks** after a clean Microsoft Defender scan, with `/W4 /WX /O2`; the native transport/icon branches also passed compile-only `/Zs`. The tests cover independent typed configuration, input rejection, exact target/argument/directory separation, post-expansion validation of environment paths, no-launch setup/error paths, real offscreen rendering, six generated PNG dimensions, stable/owner-isolated asset paths and private fixture cleanup. Process activation and system icon extraction are injected in executed tests: no applications, accounts, package registration, Startup settings or user pins were exercised. Full host integration and actual Windows activation remain separate delivery acceptance steps.

Local evidence: `build/review-validation/app-launcher-inert-oct25.log` and its Defender log. This record does not claim a completed installation or universal visual parity with another shortcut utility.
