## Source recheck after the Microsoft submission

The working tree was clean at the start of this recheck. Concrete mismatches
remain in the implementation, so passing additional tests alone cannot complete
the original request:

- `registry_notification_service.cs` passes `ServiceAutoStart` to
  `CreateServiceW`; `SecureDesktopLauncher/service_app.inc` uses
  `SERVICE_AUTO_START`. These do not meet the requested ordinary startup method.
- `DiscordRPC/drpc_core.inc` still saves tokens through
  `ProtectSecretForCurrentUser`, while the deskband account writer still calls
  `ProtectSecretString` for both secrets. These paths have no opt-in plaintext
  storage selection. Privileged service paths still enforce Program Files.
- PhotoCollage and TaskSchedulerMigration now have a shared optional tray
  editor alongside INI/CLI profiles, but Startup is still missing. Chrome and YouTube Music remain script-driven;
  their dependency extraction does not provide the requested common interface.
- Windhawk implementation files still reside under `legacy/WindhawkMods`.
  The source ownership maps cover 14 binary products and two script products;
  that inventory is not proof of complete shared behavior.
- The shared native tray helper uses `NIF_SHOWTIP` for version-4 icons and
  updates existing tooltip text. Actual hover/menu behavior across the target
  Windows versions has not been checked in this pass.
- The offline DesktopStub default-write failure has been corrected: creation,
  setting defaults and string defaults now return status, and any failure
  prevents configure-only success. The expanded inert suite passes 114 checks.

Read-only inspection also confirmed the content catalog, inside-image overlay
path and timing warning code. The warning explicitly treats 10 seconds as an
advisory threshold. Prior local logs show 282,180 model assertions, 18,826
offscreen renderer checks, 90 host/menu checks and 1,747 source checks passing;
those are scoped results, not complete Windows UI acceptance.

This pass inspected source and existing logs. It did not launch the submitted
host or exercise system integration. The missing features above remain open
independently of the separate antivirus investigation.

## Defects found and corrected in this review

1. **CI ownership failure.** `dependencies/ChromeProfileCounter` has no entry in
   the binary project map, and `ValidateProjectMap` rejects every unowned
   dependency subdirectory. Added an explicit source-product map and validation
   for script owners, preserving rejection of truly unknown folders.
2. **DesktopStub source checks read the wrong set of files.** The aggregate
   omitted `ga_content_tray.inc`, despite asserting that its catalog/prompt
   implementation was present. The wrapper-order check also skipped that
   include. Both now inspect the actual composed files.
3. **New prompt breaks generated INI and existing-profile wording.** A literal
   CR/LF in `g_stringDefaults` becomes extra INI lines because `QuoteIniString`
   only escapes quotes/backslashes. The reused `ContentSourceRestartRequired`
   key also held an old after-save message in existing profiles. Introduced a
   one-line `ContentPresetSwitchPrompt`, upgraded only unchanged old labels,
   and combined source-switch/timing warnings. Numbered entries are retained;
   concurrent edits while the prompt is open are rejected.
4. **TaskSchedulerMigration warning-as-error regression.** `Options.Help` and
   `Options.Version` remained declared after their assignments were removed.
   Removed those unused fields; the product build uses `/warnaserror+`.
5. **Profile duplication and behavior defects.** The new two managed profiles
   copied assignment/path/merge machinery, accepted an explicit empty INI path,
   created profiles during inspection, and validated bad stored values before
   replacements could repair them. `managed_profile.cs` now owns these common
   mechanics. Read-only loads use defaults without writes. Configure-only saves
   validate current prospective settings under the shared write lock; a failed
   new-file batch does not first leave behind a default INI. Combined save/show
   prints the validated committed profile. Explicit relative INI paths now use
   DesktopStub's working-directory rule; default profiles stay beside the EXE.
6. **PhotoCollage output corruption.** The same path could be selected for the
   image, log, or INI. Added distinct-path validation and a regression.
7. **Chrome integrity/quit defects retained by relocation.** The static four-
   argument `Regex.Replace(..., 1)` uses RegexOptions, not a one-match count.
   Counter replacement now validates JSON and rejects ambiguous counter keys
   before replacing the exact numeric span. Disk enumeration no longer carries
   `$Matches` across pipeline scriptblocks; unreadable registration/enumeration
   is no longer treated as an empty list. Edits check their reviewed snapshot,
   serialize this tool's writers, and back up the actual replaced file in
   `File.Replace`. `Q` now exits the enclosing loop. Chrome does not use this
   tool's mutex, so users still need to keep Chrome closed.
8. **Backup path-length regression.** Appending a GUID to an 80-character task
   name could exceed the .NET Framework build's path limit in the default deep
   checkout. The readable task-name prefix now shrinks to fit while the unique
   suffix remains intact; excessively deep backup folders fail before task
   registration.
